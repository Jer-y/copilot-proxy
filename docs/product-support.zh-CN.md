# 产品支持

## 产品定义

copilot-proxy 是面向单一可信操作者的本地协议适配器，支持将一个或多个由所有者配置的 GitHub Copilot 身份接入兼容 OpenAI 和 Anthropic 的 API，供受信任的客户端调用。

单个进程独立管理其数据目录、本地网络监听器、健康诊断及可选的全局并发限制器。每个已配置的 GitHub Copilot 身份独立维护其 Access Token、动态模型目录、故障恢复熔断状态、账号类型和可选的账号级并发限制器。客户端请求按规则确定性路由至指定账号；若目标账号不可用则直接返回失败，不负载均衡或自动故障转移。代理本身不提供下游多租户管理、用户鉴权或企业级管控功能。
## 部署支持矩阵

| 拓扑 | 支持状态 | 产品边界 |
| --- | --- | --- |
| 一名受信任用户通过本机回环地址使用 | **支持** | 符合单一操作者设计，凭据和状态保留在本机 |
| 认证网关后的私有上游 | **有条件支持** | 网关和网络必须提供下游认证、授权、限额与隔离 |
| 团队直接共享监听器 | **不支持** | 代理没有下游用户认证或租户隔离 |
| 公共多租户 API | **不支持** | 代理没有公共服务安全边界、凭据隔离、分布式限流、计费、审计或高可用控制平面 |

有条件支持私有网关，不代表绑定 `0.0.0.0` 后即可安全共享。代理必须保持私有，且只能通过认证网关访问。所需边界见[部署](deployment.zh-CN.md)。

## 非目标

公共推理托管、下游用户/API Key/租户/配额/计费/审计系统，以及高可用或分布式控制平面，需要独立架构，不能通过暴露当前进程实现。

代理既不是仅依据提供商文档判断上游能力的机制，也不是静默丢弃用户意图后仍报告成功的兼容层。
